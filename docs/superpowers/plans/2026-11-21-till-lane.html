Implementation plan · Phase 2 continued

A till you can run on a desk

Eleven tasks producing one thing: a window that scans, prices, totals, tenders and prints — with no hardware attached and no VSDC in reach.

11 tasks branch till-lane builds on 200 merged tests runs on this Mac
01 — The decomposition that matters

The sale is egui-free

LaneState holds the whole sale — the scan buffer, the basket, the tender, the fiscal sequence — and knows nothing about egui. The UI layer only renders it and feeds it keystrokes.

That single boundary is what lets tasks 7 through 10 be tested without opening a window: the hard-stop, the 999-line cap, an unknown barcode and a printer failure are all unit tests. If the sale lived inside the widget tree, none of them could be.

A keyboard-wedge scanner is a keyboard

Digits accumulate, Enter terminates. There is no device to poll in that path and no way to tell a scan from fast typing — deliberately, because that is exactly what the shop already owns.

02 — The tasks

Each ends with something that runs

TASK 1

Crate, theme, fonts

egui window in Cloud & Azure, Inter and JetBrains Mono embedded as TTFs so the counter needs nothing installed.

Proved byA test that parses the real globals.css and fails when either side drifts.
TASK 2

Money formatting

7,450 not 7450.00. Money exposes no Decimal, so this formats from its Display — the intended route.

Proved byExact strings, including 0 and 1,234,567.
TASK 3

Device traits

Printer, Drawer, Scale, ScanSource, each with a simulated implementation that records what it was asked to do.

Proved byA one-shot fail_next, so a test can provoke exactly one failure.
TASK 4

ESC/POS encoder

Bytes only, no device: init, align, bold, feed, cut, drawer kick, QR.

Proved byExact byte sequences — cut is 1D 56 42 00, and the QR length prefix is checked against its payload.
TASK 5

C5 receipt

The mandated SDC block, internal data and signature dashed every four characters, and the six-field QR payload.

Proved byThe printed VAT is 983.89 and must not be 983.90 — sum of lines, never recomputed.
TASK 6

Fiscal port

The trait Phase 3 will implement for real, plus a simulated VSDC that can succeed, reject, or be unreachable.

Proved byUnreachable returns an error and never a fabricated receipt.
TASK 7

Scanning

Keystrokes to a priced line, through classify and the catalogue.

Proved byUnknown barcode adds nothing; the 999th line refuses with an instruction, not a panic.
TASK 8

Tender and the hard stop

begin_sale → VSDC → confirm_sale → print → kick, in that order.

Proved byAn unreachable VSDC stops the lane, abandons the number, and prints nothing.
TASK 9

Printing is not the sale

A jam after the VSDC accepted the sale must not undo it.

Proved byThe sale stays confirmed and the receipt reprints byte for byte.
TASK 10

Latency budgets

The four numbers standing in for a speed gate we cannot run.

Proved byScan-to-line under 100 ms, tender-to-bytes under 300 ms.
TASK 11

The screen

Selling, hard-stop and settled, laid out from the approved mockup.

Proved by cargo run -p till-lane -- --demo — scan and tender with a keyboard alone.
03 — Review focus

The five things no happy path touches

Written with the spec open, before the tasks were drawn. Each is assigned to the task that owns the code, so none of them is left to goodwill.

  1. Task 8A scan arrives while the lane is stoppedKeystrokes during a C1 hard-stop must not quietly accumulate into a sale the cashier cannot finish.
  2. Task 7A barcode the catalogue does not haveThe cashier is told. Nothing is guessed, no line appears.
  3. Task 7The 999-line cap, mid-saleIt surfaces as "finish this sale and start another", not a panic.
  4. Task 8Under-tender, and over-tender on a cardNeither settles. Change is cash-only and capped by cash received.
  5. Task 9The printer fails after the VSDC acceptedThe sale is already fiscally done. It stays done.
04 — Boundaries

What this does not build

Deliberately out of scope

  • The signed .msi, update channel and lane pairing — Windows-specific, 2a-install.
  • The real VSDC client — Phase 3. This builds the trait and honours C1 against it.
  • Refunds, suspend/resume, X and Z reports, shift open and close.
  • Real hardware drivers.

Carried constraints

  • Whole francs at the line; tax keeps 2dp.
  • Header tax is the sum of line taxes, never recomputed.
  • sqlx macros stay off.
  • till-core and till-store are not to be modified — a need to is a finding, not a licence.
